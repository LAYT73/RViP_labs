# RViP labs

Учёт студентов. Ветки копятся: `lab-1` → `lab-2` → … Что уже собрано на той, где ты стоишь, написано внизу. Как устроены сервисы сейчас: [docs/architecture.md](docs/architecture.md).

Поднять то, что на ветке:

```bash
pnpm install
docker compose up --build
```

Клиент ходит на http://localhost:3080. Если Elasticsearch на Mac не стартует: `sudo sysctl -w vm.max_map_count=262144`. Если порт хранилища занят, задай другие: `MINIO_API_HOST_PORT=19000 MINIO_CONSOLE_HOST_PORT=19001`. Текст методички — [task/task.md](task/task.md). Решения по хранилищу и прогон тестов — [docs/lab-4-notes.md](docs/lab-4-notes.md).

## Следующая лаба

В чате Cursor две команды. Номер лабы они берут сами: текущая ветка плюс один, текст — из `task/task.md`.

1. `/lab-next` — новая ветка и спека в `openspec/changes/`. Кода ещё нет. Прочитай `proposal.md`, `design.md`, `specs/` и `tasks.md`. Не то — поправь файлы и напиши, что не так.
2. `/lab-ship` — код по `tasks.md`, проверка на поднятом стеке, архив спеки, push ветки.

Пока спеку не прочитал, `/lab-ship` не запускай.

### Как это устроено

`/lab-next` и `/lab-ship` — обычные файлы в `.cursor/commands/`. Cursor подставляет текст файла в чат, агент выполняет шаги. Постоянные запреты он и так видит из `.cursor/rules/` и [AGENTS.md](AGENTS.md). Перед опасной командой вроде `docker compose down -v` срабатывает hook из `.cursor/hooks.json` и останавливает её.

OpenSpec — папка со спекой, не отдельный сервис. `/lab-next` создаёт change через CLI `openspec`: зачем, как, что проверить, список задач. `/lab-ship` делает только этот список, потом `/opsx-archive` переносит требования в `openspec/specs/` и убирает change в архив. Следующую лабу в этот заход агент не берёт: в команде это написано прямо.

## Что уже есть

**1.** Один сервис принимает студента, правит, переводит на другой курс и отчисляет. База в Docker, таблица одна, схему накатывает Liquibase. API можно открыть в Swagger.

**2.** Второй сервис по той же базе говорит, сколько студентов на каждом курсе. Наружу оба ходят через шлюз. Коллекция для проверки — Postman.

**3.** Второй сервис с компьютера больше не открыть. Отчёт запрашивает первый сервис сам, обычным HTTP. Рядом подняты логи и трейсы: Kibana на http://localhost:5601, в ответе есть `X-Trace-Id`.

**4.** Отчёт ещё сохраняется как CSV. Отдельный сервис кладёт файл в хранилище (S3). Report отдаёт файл туда прямым HTTP-вызовом, в ответе сразу метаданные файла.

**5.** Тот же CSV больше не отправляют вызовом. Report кладёт сообщение в RabbitMQ, сервис хранилища забирает его и пишет файл. Клиент сразу получает `queued` и `jobId`.
