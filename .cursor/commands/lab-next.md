Подготовь следующую лабораторную от текущей ветки. Код приложения не меняй.

## Шаги

1. `git branch --show-current` и `git status -sb`. Ветка должна называться `lab-N`. Если есть незакоммиченные правки — остановись и напиши об этом.
2. Следующий номер — `N+1`. Прочитай в `task/task.md` только эту лабу. Если файла нет, спроси текст у человека и не выдумывай задание.
3. Прочитай `docs/architecture.md`, `openspec/specs/` и `AGENTS.md`. В Non-goals следующей спеки обязательно попадёт лаба `N+2`.
4. `git checkout -b lab-(N+1)` от текущей ветки, не от более старой.
5. Роль Architect. Кратко зафиксируй решения, от которых зависит API или границы сервисов. Если без ответа человека выбрать нельзя — задай один вопрос и остановись.
6. Если решения ясны, сделай OpenSpec change `lab-(N+1)-<короткое-имя>`: `npx @fission-ai/openspec new change "<name>"`, дальше артефакты по skill `openspec-propose` (proposal, design, specs, tasks). Код сервисов, compose и README не трогай.
7. Остановись. Дай ссылки на файлы change и напиши: прочитай их; если ок — `/lab-ship`.

Не вызывай `/opsx-apply`. Не пушь.
