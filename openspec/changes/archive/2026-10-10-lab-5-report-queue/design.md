## Context

Lab-4 sync path: report → HttpService POST → file-storage → MinIO. Lab-5 replaces the write path with a queue while keeping gateway → student → report as the public call chain.

## Goals

- Publish CSV export jobs to RabbitMQ
- file-storage consumes and stores in MinIO asynchronously
- Export HTTP response acknowledges queueing immediately

## Decisions

- Nest microservices RabbitMQ transport; queue/pattern `report.export.csv`
- Message payload: `{ filename, content, requestedAt }`
- Export response: `{ status: 'queued', jobId, rows, filename }` where `jobId` is a UUID generated by report-service
- file-storage: hybrid app — HTTP REST for read/health + RMQ consumer for writes from report
- report-service no longer requires `FILE_STORAGE_SERVICE_URL` for export
- student-service proxy remains thin HttpService forward; type updated to queued shape

## Non-Goals

- Job status polling API
- Auth, CompletableFuture

## Assumptions

- Клиент по-прежнему ходит только в gateway. Скачать CSV можно с порта file-storage, когда объект уже записан.
- `jobId` в ответе — идентификатор попытки экспорта, не ключ объекта. Ключ файла появляется позже, внутри file-storage.
- Пока consumer не обработал сообщение, `GET /api/files/:id` этого файла не существует. Отдельного статуса job нет.
- Пароли RabbitMQ и базы в `.env.example` учебные, только для локального compose.

## Alternatives

| Вариант | Почему не он |
|---------|----------------|
| Оставить синхронный POST из lab-4 | Методичка lab-5 требует очередь. При мёртвом storage клиент ждал бы ошибку, а не подтверждение |
| Писать CSV на диск report-service | Файл живёт в контейнере отчёта, file-storage и S3 из lab-4 тогда не участвуют |
| Ответ с id файла сразу | Id появляется только после PutObject. До этого честно ответить можно только `queued` |
| Опрос статуса job | В задании нет. Клиент забирает файл по id, когда тот уже есть |

Очередь нужна, чтобы экспорт не падал вместе с хранилищем: клиент получает `queued`, файл пишется, когда file-storage и S3 снова доступны. JSON-отчёт `by-course` остаётся синхронным, в очередь уходит только CSV.
